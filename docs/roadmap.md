## 当前进度判断（2026-10-21）

项目已有业务 Demo 基础，下一阶段重点是让老人端能够真实交流，并让家属实际响应。不能把后端接入成功等同于端到端产品完成。

- 2026-10-20 的 Android 12 / MIUI 实机记录覆盖双端家庭绑定、提醒反馈和离线重启同步、真实 MinIO 照片及撤权；系统权限影响本机通知。范围见 [测试说明](../tests/README.md#android-核心业务实机验证2026-10-20)，不推广为所有机型已通过。
- 最近提交已接入真实 LLM、老人端文字输入和连续会话，并修复供应商失败时的握手及 Linux 构建权限。已有虚构数据的真实供应商/WebSocket 验证记录，Android 真机真实 LLM 和 Linux 实际部署仍需分别验证；提交修复不等于部署通过。
- Android 已接入系统 ASR/TTS、现有 LLM 及按钮打断，仍需指定真机验证语音服务、中文朗读及完整连续交流。后端 ASR/TTS、Avatar 适配器及 Embedding 仍为 Mock；推送可配置 ntfy，短信/语音电话可配置 Twilio，默认关闭外发且待真实服务验收；Android 已采用独立的本地 2D 形象与实际语音状态联动；RAG 已有权限和失效控制，但 8 维模拟向量不代表真实语义检索质量。2026-10-23 已补确认、人工联系、误报、解决、处理历史和本人联系人设置；外部发送及回执接口已接入，真实供应商/真机送达待验证。

## 下一轮：先交付真实陪伴主线

顺序是“真机文字对话 → 真实语音 → 基础数字人”。A、D 可同步推进下表中的家属响应和部署工作；这里表示成员分工，不要求引入新的协作流程。

| 顺序 | 工作及负责人 | 完成时应能观察到的结果 |
| --- | --- | --- |
| 1 | **真机文字对话联调：B + C，D 配合连接**。沿用现有真实 LLM 配置和 WSS，使用虚构资料完成真机验证，记录实际等待时间并修复阻塞问题 | 老人端能连续聊多轮、停止等待、编辑失败输入；断网后明确提示，重连不自动重发；真实/Mock 标识准确，撤权后不再使用相关记忆 |
| 2 | **真实语音真机联调：B + C**。代码已采用系统 ASR → 文字 WSS/LLM → 系统 TTS，完成点击说话、识别、播音及按钮打断；指定设备检查已安装服务和中文语音。WSS 保持不上传音频，使用请求序号隔离取消结果 | 指定真机上能“说一句 → 看到识别结果 → 听到回答”，停止时取消当前处理/播放，迟到音频不继续播放；拒绝麦克风权限、识别/播音失败时可继续文字交流。默认不保存原始音频；使用真实敏感数据前确认供应商留存/训练策略 |
| 3 | **基础数字人：C 主责，B 提供播放状态**。已接入 Compose 2D 柿子形象和真实会话/系统播音回调，完成状态测试与双端构建；待指定真机验证 | 老人能看到 AI 形象、收听/思考/说话状态和随实际播音启停的基础口型；打断、失败后回到正确状态，持续明确 AI 身份 |

本轮主线完成标准：在指定 Android 真机上，使用虚构家庭资料演示一次有语音输入、真实模型回答、播音、打断和结束的连续交流。自动化测试和 APK 构建用于支持验证，不能替代这次实际交互。

## 设备化目标

kiosk/开机恢复、BLE 按钮、离线唤醒、CameraX presence、电话/OEM 兼容均未作为当前可用能力。C 主责指定平板集成，D 配合设备连接和部署，A/B 提供已有业务与语音入口。可提前核查指定平板和按钮的实际权限、连接及失败情况，功能集成按语音/联系依赖推进，再决定 SDK 和实现；失败保留普通 App、点击/文字等入口。相机不保留帧或识别人，唤醒不作身份认证，设备事件不直接决定通知和紧急状态。

没有新增每周报告、审批流水线或归档目录。一次功能修改只同步受影响文档和必要测试，不以测试数量、Mock 结果或构建成功替代真实功能证据。
